## 數據規則（寫稿前 checklist）

1. **唯一錨點**：`GET /dashboard/daily`（price_date/score_date/as_of）＋
   `GET /dashboard/daily-report-data`（structure_counts/waterfall）＋
   `GET /dashboard/podcast-script`（前一集與審查狀態）。
2. 只用**同日正式事實**；11-12 與 11-13 不拼接；即時報價（夜盤/ADR）必標「非同日，僅供參考」。
3. 缺值不補：籌碼/評分未發布 → 走誠實聲明 B 版，絕不補零或借前日充數。
4. 每個數字落稿前對照 DB（`price_volume`/`institutional_flow`/`margin_trading`/
   `three_line_scores`）或 API；無法核對者不寫。
5. 漲跌幅排行用「當日漲跌幅排序」措辭；三線最弱（weak 陣列）是另一個概念，不混用。
6. 金句收尾＋出處；結語給聽眾可執行的觀察指標，不做預測性斷言（回測/研究措辭為
   回顧性描述）。

## 播報節奏（聲音層）

- 強勢族群（如散熱）與另一族群（如 ASIC 設計服務）對比處：語氣停頓＋重音，強調資金集中度。
- 誠實聲明段放慢語速，逐句清晰——這是節目的信任資產。
- 全稿目標長度 1,000–1,300 字（約 4–5 分鐘）。

## 迭代機制

- 每日稿上傳後：審查狀態查 `GET /dashboard/podcast-script`；
  收執寫 `triline-dashboard/docs/agent_tool_receipts/podcast_script_reviews/<交易日>-<agent>.json`。
- `revise_pending` → 依 suggestions 修訂重傳；全 agent `approved` → 定版並回寫本範本。
